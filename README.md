# ربات تعیین سطح آوا

ربات تلگرام آکادمی زبان آوا با آزمون کوتاه ۱۰سؤالی انگلیسی، آلمانی، فرانسوی و ایتالیایی. خروجی، برآورد مقدماتی مبتنی بر چند پرسش دستوری است؛ **تعیین سطح معتبر یا گواهی CEFR نیست** و مهارت‌های گفتاری، شنیداری، خواندن و نوشتن را نمی‌سنجد.

## مسیر کاربر و رضایت تماس

1. با `/start` پیام معرفی و پرسش اختیاری نیت نمایش داده می‌شود. «رد کردن و رفتن به آزمون» انتخاب نیت را حذف می‌کند؛ نیت شرط آزمون یا نتیجه نیست.
2. انتخاب زبان و پاسخ به ۱۰ پرسش چهارگزینه‌ای؛ پاسخ تکراری/قدیمی پذیرفته نمی‌شود.
3. انتخاب هدف یادگیری و دریافت نتیجه شامل نمره و توضیح محدودیت برآورد.
4. پس از نمایش نتیجه، پیگیری تلفنی اختیاری است. شماره تنها با انتخاب آگاهانهٔ دکمهٔ اشتراک‌گذاری **مخاطب خود کاربر** ارسال می‌شود؛ اشتراک مخاطب دیگر یا مخاطبی بدون شناسهٔ مالک رد می‌شود. گزینه‌های «راهنمایی داخل تلگرام» و «فعلاً تماس نمی‌خواهم» بدون شماره ادامه می‌دهند. شماره و متن خصوصی در رویدادهای قیف ثبت نمی‌شود؛ در صورت پیکربندی مدیر، شمارهٔ رضایت‌داده‌شده فقط برای اعلان به مدیر فرستاده می‌شود و در SQLite ذخیره نمی‌شود.

## ذخیره‌سازی و گزارش `/report`

SQLite در `BOT_DB_PATH` قرار می‌گیرد (پیش‌فرض `ava_bot.sqlite3`). جدول `users` وضعیت آزمون را نگه می‌دارد؛ `funnel_events` تنها نام رویداد و زمان دارد، نه شناسهٔ کاربر، شماره یا متن پیام. شمارش‌ها رخدادمحور و aggregate هستند، نه شمار کاربران یکتای هر مرحله.

`/report` فقط برای شناسهٔ عددی منطبق با `ADMIN_CHAT_ID` در دسترس است. گزارش شامل شروع بات، انتخاب نیت، شروع و تکمیل آزمون، نمایش نتیجه، درخواست تماس، رد تماس/راهنمایی، رضایت اشتراک مخاطب و ارسال شماره است؛ همچنین تعداد snapshotهای کاربران و رضایت‌های تماس را نشان می‌دهد. این آمار محلی‌اند و خودبه‌خود به یک کمپین تبلیغاتی منتسب نمی‌شوند. برای تحلیل قیف به تفکیک کمپین، تعداد شروع بات، تکمیل آزمون، نمایش نتیجه و درخواست تماس را جدا ثبت/مقایسه کنید؛ در پیاده‌سازی حاضر رویدادها شناسه ندارند و امکان اتصال فردی مراحل وجود ندارد.

پایگاه قدیمی با جدول `users` هنگام راه‌اندازی با ایجاد جدول `funnel_events` سازگار می‌شود و داده‌های کاربران قبلی حذف نمی‌شوند. پیش از جابه‌جایی یا حذف DB نسخهٔ پشتیبان بگیرید.

## نصب و اجرا

نیازمند Python 3.10+ و دسترسی شبکه به Telegram هنگام اجرا:

```bash
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
export BOT_TOKEN='توکن واقعی ربات'
export ADMIN_CHAT_ID='شناسه عددی مدیر'  # اختیاری؛ اعلان شماره و /report
export BOT_DB_PATH='./ava_bot.sqlite3'   # اختیاری
python bot.py
```

در PowerShell از `$env:BOT_TOKEN='توکن واقعی ربات'` و معادل آن برای متغیرهای دیگر استفاده کنید. توکن را در GitHub commit نکنید. اگر `ADMIN_CHAT_ID` تنظیم شود باید عددی باشد.

## آزمون

از پوشهٔ پروژه اجرا کنید:

```bash
python -m unittest -v
```

آزمون‌ها به توکن یا اتصال Telegram نیاز ندارند و از SQLite موقت استفاده می‌کنند. مسیر نیت اختیاری/ردشده، آزمون و نتیجه بدون شماره، رضایت و اعتبار مخاطب، حریم خصوصی رویدادها، `/report`-data و سازگاری DB قدیمی آزموده می‌شوند.

## پیشنهاد کمپین Telegram Ads

HTML نشان می‌دهد آگهی فارسی برای `AvaLanguageAcademy_Bot` هدف‌گیری موضوعی `Education` و `Foreign Language Learning` داشته، CPM برابر **۰٫۱۵ Gram** و سقف نمایش **۱ بار برای هر کاربر در روز** داشته است. این تنظیم‌ها برای یک آزمون کم‌هزینه و جلوگیری از تکرار، فعلاً حفظ شوند. HTML عملکرد معتبری برای تصمیم بهینه‌سازی قیف ارائه نمی‌کند؛ بنابراین از CTR به‌تنهایی برای قضاوت یا ادعای برنده‌بودن متن/هدف‌گیری استفاده نکنید. دسته‌های هدف را نیز فعلاً عوض نکنید تا تغییر هم‌زمان چند عامل نتیجه را مخدوش نکند.

متن فعلی وعدهٔ «سطح واقعی»، «گزارش CEFR» و تکمیل در ۵ دقیقه می‌دهد؛ دو وعدهٔ اول با آزمون فعلی سازگار نیستند و زمان ۵ دقیقه نیز باید با زمان‌سنجی واقعی تأیید شود. متن پیشنهادی:

> 🌟 در آزمون رایگان ۱۰سؤالی آوا شرکت کن و یک برآورد مقدماتی از دانسته‌های دستوری انگلیسی، آلمانی، فرانسوی یا ایتالیایی بگیر. نتیجه رایگان است؛ این آزمون تعیین سطح رسمی یا گواهی CEFR نیست. دیدن نتیجه بدون ثبت شماره ممکن است و پیگیری تلفنی فقط با رضایت تو انجام می‌شود. 👇

اگر زمان آزمون در اجرای واقعی تأیید شد، می‌توان «در حدود ۵ دقیقه» را به متن افزود؛ در غیر این صورت عبارت زمان‌دار حذف شود. CTA مقصد همان `AvaLanguageAcademy_Bot` بماند. در دور بعدی فقط متن را تغییر دهید و CPM/سقف تکرار/هدف‌گیری را ثابت نگه دارید؛ پس از دریافت حجم کافی، چهار شاخص را جدا بررسی کنید: **شروع بات، تکمیل آزمون، دریافت/نمایش نتیجه، درخواست تماس**. در گزارش فعلی `quiz_completed` و `result_shown` جدا هستند؛ درخواست تماس با `contact_prompt_shown` شمرده می‌شود. درخواست تماس را با رضایت/ارسال شماره یکی نگیرید. برای انتساب دقیق به آگهی، ثبت تجمیعی امنِ منبع ورودی لازم است؛ داده‌های فعلی شناسهٔ رویداد ندارند.
